## 阶段 2c：A 组补充实验（2026-08-18 ~18:50 CST，全部只读/低风险）

### A1：Windows netstat 对照（注册是否生效）——决定性
- WSL 内 python http.server 18500（127.0.0.1）→ ss 确认 LISTEN
- Windows `netstat -ano | findstr 18500` → **无任何输出（端口不存在）**
- 对照：`netstat -ano | findstr :8080` → `127.0.0.1:8080 LISTENING PID=14380`（dllhost.exe，WSL 转发承载）
- 结论：**新端口注册未在 Windows 侧落地**（不是数据路径坏，是监听注册从未建立）

### A2：vsock 连通性测试（guest→host 通道）——决定性
- C 探针 vsock_probe.c：connect(AF_VSOCK) 到 VMADDR_CID_HOST(2) 的未监听端口 1/9999/ANY
- 结果：全部 **errno=110 ETIMEDOUT**（正常行为应为立即 ECONNREFUSED=111）
- 对照：guest 本地 vsock socket/bind/listen 正常（栈活着）；connect CID_LOCAL 返回 101（该实现不支持 local 环回）
- 结论：**guest→host 的 vsock 新连接失效**（请求未到达 host 驱动/无响应）——与 #41286/#40650 "hvsocket transport dies" 家族同源

### A3：vsock 状态与 dmesg 扫描
- /proc/net/vsock 不存在（该内核未暴露 proc 接口）
- dmesg 除 UtilAcceptVsock 外**无** vmbus/ring/vsock 驱动错误 → 驱动层静默失效（无错误记录）

### A4：Windows 事件日志（触发条件排查）
- 最近 3 天 sleep/resume：08-17 8:51、08-17 0:47、08-16 多次；**08-18 全天无睡眠/唤醒**
- 当前 boot：08-17 23:28（系统）+ 23:29（WSL）
- Hyper-V-Compute 近 3 天无 Error/Critical
- 结论：**故障非睡眠恢复触发**；触发条件仍未知（局限）

### A 组总结论（证据链闭合）
新端口注册失效（A1：Windows netstat 无新端口）+ vsock 新连接超时（A2：ETIMEDOUT）+ 无驱动错误（A3）+ 非睡眠触发（A4）+ kill 实验排除 relay（阶段 2）+ Windows 侧 11s 不可达（阶段 2b）→ 因果模型升级为：
**guest→host vsock 新连接失效 → localhost 转发新端口注册永不完成 → 新端口首连被拒/Windows 不可达；relay poll 超时日志为症状；会话 relay 卡死为伴生现象（#41242 家族，与首连失败无因果）**

## 阶段 3：恢复验证 + 健康对照（2026-08-18 晚，经用户授权 wsl --shutdown 后）

### R1：恢复验证（缺口②闭合）
- Windows→WSL 新端口数据转发：echo 18530 → HTTP 200，~2ms → **恢复**
- Windows netstat 显示 dllhost 37696 承载监听 → 注册机制恢复
- 结论：`wsl --shutdown` 能恢复注册链路（与严重形态恢复一致）

### H1：健康对照（推翻旧探针——重要）
- 健康态（恢复后）新端口注册延迟实测：**50–100ms**
- `t=0` 立即拨号 ×10：**10/10 必失败（健康态）**
- 结论：旧探针"listen 后立即拨号 ×10"在健康态必然 FAIL → **探针设计缺陷**；阶段 0/2c 的客侧读数（E1/E3a/E3b 的 0/10）**全部作废**，不能作为故障证据

### H2/H2b：vsock 对照（推翻"vsock 失效"）
- H2：扫描宿主端口 1–512 → 全 ETIMEDOUT（未监听端口超时是**正常行为**）
- H2b：50000/50001/50002/50005 → **CONNECTED**（guest→host vsock 通道活着）
- 结论：旧"新D：vsock 失效"撤销；A2 的 ETIMEDOUT 读数同样不能作为故障证据

### H3：健康态瞬态复现（新发现，可作微软 issue Repro from healthy）
- 同一进程内连续"listen→连接→curl→关闭"多轮：第 1 轮必过，**第 2 轮起新端口注册停滞 >2s**（Go 探针 5 次运行 5/5 命中；第 3 轮部分恢复）
- 独立进程（间隔 1s）：4/4 全过；进程内间隔 3s：3/3 依然失败 → **不是时间恢复，是进程内"会话拆除竞争"**
- 瞬态自愈：t+2s/5s/15s/30s 后注册恢复；全程 dmesg UtilAcceptVsock 计数 = 0
- 结论：严重形态（小时级、dmesg 增长、Windows 侧不可达）与健康态瞬态（2–5s 自愈、无 dmesg）是**两个独立形态**

### 阶段 3 总结论（最终）
- 仍有效的故障证据（严重形态）只剩：Windows 侧新端口 curl ≥10s 000 + Windows netstat 无新端口（A1）+ 长存活 8080 正常（E9）+ 复用端口可注册
- 探针语义修正：单轮 + 时延测量 + Windows 侧 curl 校验（健康态 4/4 PASS）；`-attempts 3 -delay 0` 复现瞬态 WARN 1/3
- 上游 issue 报告角度：健康态瞬态注册失效（Repro from healthy）+ 严重形态为补充
