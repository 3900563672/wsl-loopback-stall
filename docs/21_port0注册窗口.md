# 21 端口 0 注册失败窗口测量：二元结果、永久丢失、窗口式出现（#40187 未修复实证 II）

> 日期：2026-08-19 ｜ 类型：健康态批量测量（guest 侧，无管理员权限）｜ 状态：完成
> 探针：local/port0/port0_*.go（6 个，全部可复现）

## 测量矩阵（本轮新增）

| 实验 | 场景 | 端口 0 成功率 | 注册延迟 | 备注 |
| --- | --- | --- | --- | --- |
| poll（20 轮） | bind(0) → 100ms 轮询 5s | 6/20（30%） | 成功全部 101-102ms | 二元：≤~100ms 或 5s 永不 |
| pair A（25 轮） | bind(0) → 100ms 轮询 4s | 19/25（76%） | 成功 ~200ms 内 | 失败成块：轮 11-12、19-24 |
| pair B（25 轮，并行进程） | 同上 | 23/25（92%） | 同上 | 失败：轮 16、19；**与 A 不同步** |
| mix（40 轮交替） | 交替 bind(0)/显式，sleep 1.5s | 17/20（85%） | ≤1.5s | **故障窗口（轮 28-34 四连败）内显式端口全 OK** |
| longpoll（6 轮） | bind(0) → 1s 轮询 60s | 3/6（50%） | 成功全部 ≤1s | **失败 3 轮 60s 内永不注册；连续 180s 失败窗口** |

## 核心结论

1. **二元结果**：端口 0 注册要么 ≤1s 内成功，要么永久丢失（60s 窗口内不补注册，无中间态、无延迟注册）。
2. **窗口式出现**：成功率在时间上成块波动——健康窗口 ~100%，故障窗口 0%；故障窗口持续秒级（pair A 21s）到分钟级（longpoll 连续 180s）。
3. **路径特异性**：故障窗口内显式端口 100% 成功 → 故障只在端口 0 特有路径（dup fd + 异步 getsockname + RequestPort）。
4. **每进程独立**：双进程并行时失败窗口不同步 → 丢失点与每进程的 seccomp 通知/pidfd 路径相关，非 wsldevicehost 全局故障。
5. **bind 全部成功**：所有实验 bind() 返回 0 → HandleRequest 未被调用或返回 0（缓存命中）→ 与"ResolvePortZeroBind 失败（getsockname 未取到端口）→ 不注册、bind 照常放行"的代码路径自洽（GnsPortTracker.cpp 端口 0 分支：`CompleteRequest` 先放行 → 异步 `ResolvePortZeroBind` → 失败仅记日志）。

## 机制推断（#40187 修复前实现的竞态）

- 2.7.8.0（DLL 04-20 构建）使用 #40187（04-22）修复前的实现：dup socket（pidfd_getfd）→ 放行 bind → 异步 getsockname（25×10ms=250ms 轮询）→ HandleRequest。
- **修正（22 号文档，2026-08-19 ETW 实证）**：故障窗口内注册请求从未到达 wsl_devicehost（host 侧 0 个 port request 事件）——失败点在 guest→host 消息路径，不是 host 侧 ResolvePortZeroBind；"异步 getsockname 解析失败"假设已被排除（host 根本没收到请求）。
- 触发条件未知：guest 未发或消息传输丢失（本轮无法区分），需 guest 侧 tracing 才能钉死（超出本机可观测范围）。
- 叠加 #41051（线程场景 pidfd_open 失败，08-05 修复，2.7.8.0 不含）→ 并发场景成功率塌缩到 2.3%。

## 与退化态的关系

- **退化态"注册不再物化" = 本机制的极端形式**：健康态下故障窗口分钟级且自恢复；退化态（数小时压力）下窗口无限延长。两者共享"注册静默丢失"语义。
- 实证价值：健康态可复现的"窗口式注册丢失"（成功率 0-100% 波动、永久丢失、显式端口免疫）是比退化态更干净、可一键复现的证据——官方 #40187 已承认同类问题并修复，2.7.8.0 未含修复。
- **明确不主张为新 bug**；作为"版本缺陷区间（缺 #40187/#41125/#41051）内健康态可观察的注册丢失"实证。
