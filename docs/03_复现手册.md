# 03 WSL 回环实验复现手册

> 日期：2026-08-19 ｜ 目的：独立复现全部关键实验（每项 → 命令 / 预期 / 耗时 / 依赖态）
> 工具基线：`tools/wsl-loopback-probe/main.go`（构建产物 `wsl-localhost-probe`）

## 0. 使用说明

- 本手册只回答"怎么复现、复现到什么算数"；结论与证据链见 01/02/08/12/13 号文档。
- **环境基线**（复现前必须确认）：Windows 11 build 26200.9168 ｜ WSL 2.7.8.0 ｜ Ubuntu 26.04 ｜ 内核 6.18.33.1 ｜ Consomme 网络模式。
- **两种系统形态**（所有实验先分清在哪种形态下做）：
  - 健康态：新端口注册 50-100ms，Windows 侧可达；健康态瞬态（进程内 churn）2-5s 自愈。
  - 退化态（严重形态）：Windows 侧新端口 ≥10s 不可达（curl 000）、Windows netstat 无新端口；**不可一键复现**（数小时压力触发，概率性），只能识别 + 现场收集。
- 判定任何"故障"前，先跑 E1 确认健康基线；健康态下探针"立即拨号 ×10"必失败（旧探针坑，见第 5 节）。

## 2. 实验矩阵

### E1 健康态基线（每次复现前必跑）

```bash
cd tools/wsl-loopback-probe
./wsl-localhost-probe -rounds 3 -timeout 10s -wincheck
```

- **预期**：3/3 PASS；first-success ≈ 50-100ms；win=ok:XXms。
- **耗时**：约 1 分钟。**依赖**：健康态。
- 若 win=UNREACHABLE > 10s → 系统可能已退化，先 E9 判定再决定是否继续。

### E2 健康态瞬态（进程内 churn —— 微软 issue 的 Repro from healthy）

```bash
./wsl-localhost-probe -rounds 5 -timeout 30s
```

- **预期**（2026-08-18 实测 5 次运行 5/5 命中）：第 1 轮必过（~52ms）；**第 2 轮起注册停滞 >2s**（最多约 5s 后自愈）；第 3 轮部分恢复。
- 判据：round 2 的 first-success ≥ 2s 即为命中瞬态；若 5 轮全快（<200ms），等 30s 重跑。
- **耗时**：2-3 分钟。**依赖**：健康态（退化态下是另一回事）。
- 对照（证明"不是时间恢复，是进程内会话拆除竞争"）：独立进程间隔 1s 连跑 4 次 → 4/4 全过；同进程内间隔 3s 连跑 3 次 → 3/3 仍失败。

### E3 固定端口对照（免疫证明）

```bash
./wsl-localhost-probe -rounds 29 -timeout 10s -wincheck -fixed 28999
```

- **预期**：29/29 PASS 且 first-success < 1.1ms（历史数据：T1 15/15 <1ms；V6 8/8 0.7-1.1ms）。若 `-fixed` 端口被占用（TIME_WAIT 冲突）会 listen failed，换一个空闲端口（如 28999 → 29001）。
- **耗时**：约 1 分钟。**依赖**：健康态。
- 意义：固定端口同步注册路径免疫 → 问题锁定在 ephemeral（port-0）延迟注册路径。

### E4 200 轮时延直方图（独立 issue 报告素材）

```bash
./wsl-localhost-probe -rounds 200 -timeout 30s -wincheck > hist200.log 2>&1
```

- **预期**：summary 行 `ok=200/200`；latency min≈50-100ms；注意 p90/p95/p99 与 max 的拖尾（健康态瞬态会贡献 >2s 的样本）。
- **耗时**：10-15 分钟。**依赖**：健康态（退化态跑无意义）。
- 产物：hist200.log（附在独立 issue 或回复中）。

### E5 双进程并发 churn（全局性证明，C5）

```bash
# 终端 A
./wsl-localhost-probe -rounds 30 -timeout 30s
# 终端 B（同时启动）
./wsl-localhost-probe -rounds 30 -timeout 30s
```

- **预期**：两进程双双出现 STALL/长停滞（连接表与锁全局，进程无关）。
- **耗时**：3-5 分钟。**依赖**：健康态。

### E6 陈旧积压剂量响应（T5）

构造"有连接历史"的陈旧端口（每个端口：listen → accept 一次连接 → 关闭连接 → **保持 listener 存活**），数量 0 / 1-3 / 5-6 三档；随后在同一进程跑 8 轮 ephemeral churn：

```bash
# 构造 N 个陈旧端口（Python 示例，N 按剂量档位 0/3/6）：
python3 - <<'PY'
import socket, threading, time
stale = []
for i in range(6):            # 0 / 3 / 6 三档
    s = socket.socket(); s.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
    s.bind(("127.0.0.1", 0)); s.listen(1); stale.append(s)
    # 制造"有连接历史"：accept 一次后关闭连接，listener 保持
    def hit():
        c, _ = s.accept(); c.close()
    threading.Thread(target=hit, daemon=True).start()
    socket.create_connection(("127.0.0.1", s.getsockname()[1])).close()
time.sleep(1)   # 等 accept 完成
print("stale ports:", [s.getsockname()[1] for s in stale])
time.sleep(600) # 保持进程存活期间，另开终端跑探针
PY
# 另开终端（同一 WSL 会话）：
./wsl-localhost-probe -rounds 8 -timeout 30s
```

- **预期**（T5 实测）：0 陈旧 → 0/8 卡；1-3 陈旧 → 3/8 卡 >30s；5-6 陈旧 → 3/3 卡。
- **耗时**：每档 10-20 分钟。**依赖**：健康态。
- 注意：原始实现为一次性脚本未保留，以上为**等价重建**，判据与 journal 阶段记录一致。

### E7 端口保留时长（有连接历史 60-75s + WSAEADDRINUSE，V7/V10/V12）

```bash
# 1) 构造有连接历史的端口（同 E6 构造段，listener 保持）
# 2) Windows 侧观察 dllhost 是否仍持有该端口（保留窗口内）：
netstat -ano | findstr <port>          # 预期：127.0.0.1:<port> LISTENING PID=<dllhost>
# 3) 关闭 listener 后继续观察注销延迟（10s 一次 netstat）：
#    预期：无连接历史端口 ~1.3s 注销（V10a）；有连接历史端口 60-75s 才注销（V10b/c 63s）
# 4) 保留窗口内 Windows 侧绑定同端口（V12）：
#    PowerShell: (New-Object Net.Sockets.TcpListener([Net.IPAddress]::Loopback, <port>)).Start()
#    预期：WSAEADDRINUSE（端口被 dllhost 占用）
```

- **耗时**：每个端口 2-5 分钟。**依赖**：健康态。
- 意义：解释"CloseWait+Listen 并存"、"WSAEADDRINUSE"、60-75s 保留 = TimeWait 无定时器（`tcp.rs` TODO）+ 等连接排空。

### E8 退化态识别与现场收集（严重形态，**不可一键复现**）

- **识别**（当前系统处于退化态的判据）：
  1. E1 探针 win=UNREACHABLE（Windows 侧新端口 30s 不可达）；
  2. Windows `netstat -ano | findstr <新端口>` 无该端口（注册未落地）；
  3. 长存活端口（如 8080）仍 200 → 只影响新端口注册。
- **复现路径（数小时压力，概率性）**：反复跑 E2/E5/E6 + 杀 dllhost + 长时间 churn（2026-08-18 实测为 V8-V12/T1/T3/T5 大量 churn + kill dllhost + WPR 95GB 录制期间触发）。**不要承诺"一键复现"**，需现场收集（按 E10）。
- 退化态现场复现示例（2026-08-18 22:27 官方录制窗口内实测 `repro_during_capture2.log`）：
  `./wsl-localhost-probe -rounds 8 -timeout 30s -wincheck` → 前 3 轮 guest 12ms 成功但 win=UNREACHABLE > 30s（半黑洞），第 4-8 轮 guest 侧也 STALL（全黑洞）。

### E9 官方日志收集 + 录制窗口内复现（已跑通，22:27-22:31）

```powershell
# 1) 提权运行（UAC 弹窗）：官方 collect-wsl-logs.ps1（-LogProfile networking，本地 wrapper 提权）
# 2) 录制开始后（约 30-60s 内），WSL 内跑复现：
cd tools/wsl-loopback-probe

# 3) 收集完成 → 产出 tar.gz（约 100MB），解压归档
```

- **预期**：录制窗口内探针出现半黑洞/全黑洞轮次 → 失败现场在官方日志包内。
- **耗时**：10-30 分钟（含提权）。**依赖**：退化态优先（健康态也能录，但无失败现场）。
- 踩坑：WPR 必须成对启停（脚本已内置重试/清理）；WSLg 收集可能挂起（脚本有超时）；首次运行前先 `wpr -cancel` + `pktmon stop` 清残留。

### E10 WPR trace 解码与探针端口证据提取

```powershell
# 在本地研究目录执行（勿落系统 Temp；解码 XML 约 8.8GB）
tracerpt logs.etl -of XML -o wpr-dump.xml
# 提取探针端口证据（1,312 条归档于本地证据目录）
# 关键证据形态：
#   "TCP: Tcb ... requested to connect"
#   "IP: Transmitting loopback Nbl ... Src=127.0.0.1:<端口> Dst=127.0.0.1:<端口>"
```

- **预期**：探针端口在 TCPIP/IP provider 中出现"连接失败/虚拟回应"事件（2026-08-18 实测 36 条 requested to connect + 165 条 loopback NBL）。
- **耗时**：30-60 分钟 + 8.8GB 磁盘。**依赖**：已有 logs.etl。
- 方法论：**pktmon 对此问题无效**（中继在用户态栈，不经 NDIS/vmswitch；两次捕获 53.8 万包中继帧 0）——证据只能来自 ETW/WPR。

### E11 vsock 通道对照（H2/H2b）

```c
// vsock_probe.c（重建模板，原文件随 /tmp 丢失）：
// connect(AF_VSOCK, {CID=VMADDR_CID_HOST(2), port=<目标>})
// 编译：gcc -o vsock_probe vsock_probe.c
```

- **预期**：已监听端口 50000/50001/50002/50005 → CONNECTED；未监听端口 → ETIMEDOUT（**这是正常行为，不是故障证据**，H2 教训）。

- 意义：排除"vsock 通道整体失效"；退化态故障点在注册链路而非数据通道本身（结合 A1 netstat 无新端口）。

### E12 恢复验证（wsl --shutdown）

```powershell
wsl --shutdown   # 会关所有发行版 + Docker 依赖的 WSL 引擎，执行前确认无其他运行任务

# WSL 内：

```

- **预期**：3/3 PASS + win=ok（恢复后 Windows→WSL 新端口转发 ~2ms HTTP 200）。
- **耗时**：5-10 分钟。**依赖**：需授权。
- 恢复后若需补做 E4（200 轮直方图），先等 5 分钟让系统稳定。

## 3. 常见误判清单（每条都是踩过的坑）

| 误判 | 真相 |
| --- | --- |
| "listen 后立即拨号 ×10 失败 = 故障" | 健康态下 t=0 立即拨号 **10/10 必失败**（注册延迟 50-100ms）；旧探针结论全部作废 |
| "vsock 未监听端口 ETIMEDOUT = 通道失效" | 未监听端口超时是正常行为；要测已知存活端口（50000-50005） |
| "accept(11) 是 errno 11=EAGAIN" | 11 是 SocketFd 编号；日志语义 = poll 60s 超时循环 |
| "健康态瞬态 = 严重形态" | 两个独立形态：瞬态 2-5s 自愈、dmesg 计数 0；严重形态小时级、dmesg 持续增长 |
| "2-5s 自愈是普适行为" | 只反映低积压状态；陈旧累积后 >90s 不可达（T3） |
| "进程内 churn 卡 = 时间不够" | 独立进程 1s 间隔全过、同进程 3s 间隔仍卡 → 会话拆除竞争，非时间 |
| "pktmon 抓不到 = 没流量" | Consomme 中继在用户态栈，包级抓包无效；证据在 ETW |
