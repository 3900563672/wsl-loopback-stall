# 09 环境恢复与 WSL 版本回滚指南

> 日期：2026-08-19 ｜ 适用范围：Windows 11 + WSL2（Ubuntu，Consomme 网络模式）环境

## 0. 总原则（先读，违反必出事故）

1. **敏感操作矩阵**（执行前确认无其他重要任务在跑）：

| 操作 | 影响 | 要求 |
| --- | --- | --- |
| `wsl --shutdown` | 关所有发行版 + Docker 依赖的 WSL 引擎 | 确认无运行任务后执行 |
| `wsl --update` / `--pre-release` | 更新会重启 WSL；可能改变网络行为 | 确认后执行，可回滚（第 3 节） |
| 整机重启 | 全部服务中断 | 确认后执行 |
| 探针 / 日志收集 / 只读分析 | 无副作用 | 不需要 |

2. **三不**：不动代理配置；不删 Docker 数据（先查挂载）；复杂文件删除走 WSL `rm`。
3. 任何"数据没了/端口没了/卷没了"的第一反应是**查证据**，不是重置。

## 1. 快速健康检查（故障第一反应，10 秒）

```powershell
# 1) WSL 回环转发是否健康（探针目录，3 轮基线）
wsl -d Ubuntu -- bash -lc "cd tools/wsl-loopback-probe && ./wsl-localhost-probe -rounds 3 -timeout 10s -wincheck"
#   预期：3/3 PASS + win=ok；若 win=UNREACHABLE → 退化态（见第 2 节）

# 2) WSL 发行版状态
wsl -l -v
```

## 2. WSL 退化态恢复（2026-08-18 场景）

- **症状**：探针 win=UNREACHABLE（Windows 侧新端口 30s 不可达）+ Windows netstat 无新端口 + 长存活端口正常。
- **恢复**：唯一已知方式 `wsl --shutdown` → 完整步骤见 **08_系统恢复操作步骤.md**（保存现场 → shutdown → 启动验证 → 最终验证）。**执行前确认无其他运行任务**。

## 3. WSL 版本更新与回滚

### 3.1 查看与更新

```powershell
wsl --version                      # 记录当前版本
wsl --update                       # 更新到最新 stable（Store 分发）
wsl --update --web-download        # 从 GitHub 下载更新（绕过 Store 缓存问题）
wsl --update --pre-release         # 更新到 Preview
wsl --shutdown                     # 更新后建议重启 WSL 生效（确认后执行）
```

### 3.2 回滚到指定版本

1. 从 microsoft/WSL GitHub Releases 下载目标版本的 `.msixbundle`；
2. `Add-AppxPackage -Path <下载的.msixbundle>` 覆盖安装（同架构 x64）；
3. 若提示版本冲突：`Get-AppxPackage *WindowsSubsystemForLinux* | Remove-AppxPackage` 后重新安装目标版本（发行版数据在独立 vhdx，不会丢失；保险起见先记录 `wsl --version` 与 `.wslconfig` 内容）；
4. 安装后 `wsl --version` 确认 + 跑第 1 节探针基线。
5. **实测修正（2026-08-19）**：`Add-AppxPackage` 只更新 Store 身份，**不会替换 `C:\Program Files\WSL\` 二进制**（wsl.exe / wsldevicehost.dll 仍为旧版，`wsl --version` 也不变）。必须再以管理员安装同版本 x64 MSI（`msiexec /i ... /qn`）才完成文件层回滚。完整实测流程见 10 号文档第四节；仅回滚 Appx 包会导致"包版本与运行文件不一致"的假成功状态。

### 3.3 回滚风险与验证

- 回滚后必须重跑第 1 节探针基线 + 固定端口对照，确认环境回到已知健康态。
- 版本切换会让 WSL 服务重启（等效一次 `wsl --shutdown`），Docker Desktop 等依赖 WSL 引擎的软件会受影响。

## 4. 日志采集注意事项（WPR / ETL）

1. **WPR 必须成对启停**：`wpr -start` 后无论成功失败都要 `wpr -stop` 或 `wpr -cancel`，结束立即检查 `%TEMP%` 下 `*.etl` 大小；
2. 禁止无上限 System Collector 直录系统盘；长录制用 `-FileMode` / MaxFileSize；
3. ETL/转储/解码产物默认落独立 logs 目录，不落系统盘 Temp；WPR 解码 XML 可达 GB 级，用完即删（18 号文档）。
4. 删除走 WSL `rm`（复杂路径删除更可靠）。

## 5. 故障速查表

| 症状 | 第一反应 | 引用 |
| --- | --- | --- |
| WSL 新端口不可达 | 探针判定形态（健康瞬态/退化态） | 03 号 E1/E8 |
| WSL 更新后行为变化 | 回滚（3.2）+ 重测基线 | 本节 3 |
| 探针 win=UNREACHABLE 但业务正常 | 退化态只影响新端口；按需决定是否恢复 | 08 号文档 |
