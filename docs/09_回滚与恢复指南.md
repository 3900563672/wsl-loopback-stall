# 09 回滚与恢复指南（本机环境总纲）

> 日期：2026-08-19 ｜ 用户强调："后面既要重启环境，又要做各种回滚或版本更新，必须有一套不会再出事故的完整指南"
> 适用范围：本机（Windows 11 build 26200.9168 / WSL 2.7.8.0 / Ubuntu 26.04 / Docker Desktop + 内置 K8s / D 盘 Docker 数据盘）

## 0. 总原则（先读，违反必出事故）

1. **敏感操作矩阵**（执行前必须用户在场授权）：

| 操作 | 影响 | 授权要求 |
| --- | --- | --- |
| `wsl --shutdown` | 关所有发行版 + Docker 依赖的 WSL 引擎；K8s 节点容器不自动恢复 | **必须授权**（08 号文档） |
| `wsl --update` / `--pre-release` | 更新会重启 WSL；可能改变网络行为 | **必须授权**（本节 3） |
| Docker Desktop 重启 / Reset Kubernetes | 节点容器不自动恢复；Reset 会清集群 | 重启可授权；Reset **慎用** |
| 整机重启 | 用户 Agent 项目在跑 | **必须授权** |
| UAC 提权操作 | 弹窗 | 用户在场点"是" |
| 探针 / 日志收集 / 只读分析 | 无副作用 | 不需要 |

2. **三不**：不动代理配置（127.0.0.1:7890）；不删 Docker 数据（先查 Junction）；不用 PowerShell Remove-Item 删复杂路径（策略拦截，删除走 WSL `rm`）。
3. **提权模式**：写 .ps1 脚本 → `Start-Process powershell.exe -Verb RunAs -WindowStyle Hidden` → 日志落 %TEMP% → 轮询日志确认（用户会看到 UAC 弹窗）。
4. 任何"数据没了/端口没了/卷没了"的第一反应是**查证据**，不是重置（见第 8 节速查表）。

## 1. 快速健康检查（故障第一反应，10 秒）

```powershell
# 1) WSL 回环转发是否健康（research 目录，3 轮基线）
wsl -d Ubuntu -- bash -lc "cd /mnt/c/Users/hh/OneDrive/research && ./wsl-localhost-probe -rounds 3 -timeout 10s -wincheck"
#   预期：3/3 PASS + win=ok；若 win=UNREACHABLE → 退化态（见第 2 节）

# 2) WSL 发行版状态
wsl -l -v

# 3) Docker 与数据盘（若显示 0 容器/0 卷 → 先查 Junction，禁止重置！）
docker ps
dir C:\Users\hh\AppData\Local\Docker\wsl\disk    # 应看到 112GB 的 docker_data.vhdx

# 4) 内置 K8s
kubectl get nodes        # 预期 desktop-control-plane + worker 等节点

# 5) C 盘余量（<10GB 先查第 5 节大文件）
Get-PSDrive C
```

## 2. WSL 退化态恢复（2026-08-18 场景）

- **症状**：探针 win=UNREACHABLE（Windows 侧新端口 30s 不可达）+ Windows netstat 无新端口 + 长存活端口正常。
- **恢复**：唯一已知方式 `wsl --shutdown` → 完整步骤见 **15_系统恢复操作步骤.md**（保存现场 → shutdown → 启动验证 → 恢复 Docker/K8s → 最终验证）。**执行前必须用户授权**。

## 3. WSL 版本更新与回滚（#63 会用到）

### 3.1 查看与更新

```powershell
wsl --version                      # 记录当前版本（本机 2.7.8.0）
wsl --update                       # 更新到最新 stable（Store 分发）
wsl --update --web-download        # 从 GitHub 下载更新（绕过 Store 缓存问题）
wsl --update --pre-release         # 更新到 Preview（#63 跨版本测试用）
wsl --shutdown                     # 更新后建议重启 WSL 生效（需授权）
```

### 3.2 回滚到指定版本（如 2.7.8.0）

1. 从 microsoft/WSL GitHub Releases 下载目标版本的 `.msixbundle`（如 2.7.8.0）；
2. `Add-AppxPackage -Path <下载的.msixbundle>` 覆盖安装（同架构 x64）；
3. 若提示版本冲突：`Get-AppxPackage *WindowsSubsystemForLinux* | Remove-AppxPackage` 后重新安装目标版本（**卸载会丢失用户态配置吗？不会，发行版数据在独立 vhdx；但保险起见先记录 `wsl --version` 与 `.wslconfig` 内容**）；
4. 安装后 `wsl --version` 确认 + 跑第 1 节探针基线。
5. **实测修正（2026-08-19，#71 回滚）**：`Add-AppxPackage` 只更新 Store 身份，**不会替换 `C:/Program Files/WSL/` 二进制**（wsl.exe / wsldevicehost.dll 仍为旧版，`wsl --version` 也不变）。必须再以管理员安装同版本 x64 MSI（`wsl.2.7.8.0.x64.msi`，`msiexec /i ... /qn`）才完成文件层回滚。完整实测流程见 10 号文档第四节；仅回滚 Appx 包会导致“包版本与运行文件不一致”的假成功状态。

### 3.3 更新/回滚风险清单

- 更新会重启 WSL 服务（等效一次 `wsl --shutdown`），Docker/K8s 会受影响 → **必须授权 + 选用户空闲时段**；
- 新版本可能改变网络模式/中继行为（Consomme 是 2.7.x 默认演进方向）→ 更新后**必须**重测探针基线 + Windows 侧业务端口（8080）；
- 不要手动覆盖 `C:\Program Files\WSL\` 下的文件（Store 管理，手动覆盖会导致版本不一致——该目录当前就有 wsl.exe 06-06 与 wsldevicehost.dll 04-20 混装的现象，属正常更新节奏，但不要人为加剧）；
- Preview 测试计划（#63）：测完用 3.2 回滚 stable；测试前先跑第 1 节基线留档。

## 4. Docker Desktop 恢复（含内置 K8s 与数据盘）

### 4.1 启动与 K8s 恢复

1. 启动 Docker Desktop（托盘图标变绿约 1-3 分钟）；`docker ps` 应显示既有容器；
2. **内置 K8s 不会自动恢复**（2026-08-16 强杀事故实证）：Settings → Kubernetes → 勾选 Enable Kubernetes → Apply & Restart；等 `kubectl get nodes` 全部 Ready（desktop-control-plane + worker 等）；
3. 若仍未恢复：Settings → Kubernetes → **Reset Kubernetes Cluster**（清空集群内资源，**慎用**，只在内置 K8s 起不来时用；会丢 CR/CRD/PVC 数据）；
4. 项目恢复：`bash setup.sh`（只复用 docker-desktop context；不创建/重置集群）→ 一键启动验证。

### 4.2 数据盘（D 盘 vhdx）——**任何"卷/容器消失"先查这里**

- 布局：`C:\Users\hh\AppData\Local\Docker\wsl\disk` 是 **Junction** → `D:\DockerData\DockerDesktopWSL\disk\docker_data.vhdx`（112GB，2026-08-16 迁移）。
- 检查命令：

  ```powershell
  Get-Item 'C:\Users\hh\AppData\Local\Docker\wsl\disk' | Select LinkType,Target   # 预期 Junction + D:\DockerData\...
  dir 'C:\Users\hh\AppData\Local\Docker\wsl\disk'                                # 预期看到 112GB docker_data.vhdx
  ```

- **若 Junction 丢失**（Docker 显示 0 容器/0 卷）：
  1. 退出 Docker Desktop；
  2. 检查默认位置是否被 Docker 静默新建了空 vhdx（约 1.5GB，有则先移走备份，**不要删**）；
  3. 重建 Junction（需管理员，UAC 模式）：`New-Item -ItemType Junction -Path 'C:\Users\hh\AppData\Local\Docker\wsl\disk' -Target 'D:\DockerData\DockerDesktopWSL\disk'`；
  4. 启动 Docker Desktop 验证 `docker ps` / `docker volume ls` 恢复；
  5. **绝不**执行 Docker 重置/删除 vhdx 来"修复"。
- 说明：`settings-store.json` 的 DataFolder 对 WSL2 引擎**不生效**（硬编码找 `%LOCALAPPDATA%\Docker\wsl\disk`），Junction 是唯一挂载机制。

### 4.3 bind 挂载坑（issue #54/#56）

- kind 5 节点清单 `extraMounts` 指向 Docker Desktop 根文件系统（非持久）；节点容器/Docker Desktop 重启后 bind 失效 fallback tmpfs → PVC 数据面故障。
- 现状：临时方案（5 节点 umount + 哨兵 v2）会随重启丢失；**根治需重建集群**（issue #50 底座迁移方向）——日常遇 bind 失效，按 08 号文档恢复序列 + 检查 PVC 数据，勿当普通 bug 反复重启。

## 5. C 盘防护规则（血泪教训：95GB 事故）

1. **WPR 必须成对启停**：`wpr -start` 后无论成功失败都要 `wpr -stop` 或 `wpr -cancel`，结束立即检查 `%TEMP%` 下 `*.etl` 大小；
2. 禁止无上限 System Collector 直录 C 盘（95.8GB 事故根因）；长录制用 `-FileMode` / MaxFileSize；
3. 长会话结束前例行扫描大文件：

   ```powershell
   Get-ChildItem "$env:TEMP" -File | Sort Length -Descending | Select -First 15 Length,FullName
   ```

4. 删除走 WSL rm（PowerShell Remove-Item 复杂路径被策略拦截）：

   ```powershell
   wsl -d Ubuntu -- bash -lc "rm -f '/mnt/c/Users/hh/AppData/Local/Temp/xxx.etl'"
   ```

5. ETL/转储/解码产物默认落 `logs\`（或 D 盘），不落 C 盘 Temp；WPR 解码 XML 8.8GB 级别，用完即删（18 号文档）。
6. 虚拟内存/分页问题：pagefile.sys（27GB）迁移 D 盘需整机重启（未授权未做）；C 盘余量紧张时先按本节 3/4 清理，不要立刻重启。

## 7. 明天的恢复序列（#62：Docker 排除测试 + 200 轮直方图）

用户授权后按序执行（对应 08 号文档 + 03 号手册）：

1. 保存现场（日志已齐，一般跳过）；`wsl --shutdown`；启动 Ubuntu；
2. **先不起 Docker**：探针 8 轮（`-rounds 8 -timeout 10s -wincheck`）→ 判定"无 Docker 是否健康"（Docker 排除对照）；
3. 启动 Docker Desktop + 手动 Enable 内置 K8s（4.1 节）；
4. 起 Docker 后复测 8 轮 + 业务端口 8080；
5. 健康确认后跑 200 轮直方图（03 号 E4，10-15 分钟）；
6. 结果归档：hist200.log → research\ + Documents/；对照"无 Docker vs 有 Docker"两套读数写入 18 号文档附录。
