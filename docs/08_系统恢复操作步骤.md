# 08 系统恢复操作步骤（WSL 退化态 → 健康态）

> 场景：2026-08-18 深夜，WSL 处于"新端口注册失效"退化态（严重形态，实验压力导致）。
> 表现：guest 内新端口 1-12ms 注册成功，但 Windows 侧 30s+ 不可达；netstat 无 LISTEN、有 curl TIME_WAIT（虚拟握手黑洞）。
> 唯一已知恢复方式：`wsl --shutdown`（2026-08-18 白天验证过恢复成功）。

## 前置确认（恢复前必读）

- ⚠️ `wsl --shutdown` 会关闭**所有** WSL 发行版（含当前发行版）和 Docker Desktop 依赖的 WSL 引擎
- ⚠️ 执行前确认当前没有其他重要任务在跑
- ⚠️ 不要动代理配置（如系统代理 127.0.0.1:7890）
- ✅ 研究材料已归档，WSL 重启无丢失风险

## 恢复步骤

### 第 1 步：保存现场（可选，5 分钟）

如果还想保留退化态现场（日志已收集，一般不需要）：

```powershell
netstat -ano > degraded-netstat.txt
```

### 第 2 步：执行 wsl --shutdown

```powershell
wsl --shutdown
```

- 无输出即成功；可用 `wsl -l -v` 确认所有发行版为 Stopped
- 若 Docker Desktop 正在运行，建议先退出 Docker Desktop（托盘图标右键 → Quit），避免它自动拉起 WSL

### 第 3 步：重新启动 WSL 并验证健康态

```powershell
wsl -d <发行版名>
```

在 WSL 内：

```bash
cd tools/wsl-loopback-probe
./wsl-localhost-probe -rounds 3 -timeout 10s -wincheck
```

**健康标准**：
- round 1 first-success ≈ 50-100ms（健康态注册延迟）
- win=ok:XXms（Windows 侧可达）
- 3 轮全部正常

补充对照（固定端口）：

```bash
./wsl-localhost-probe -rounds 1 -timeout 10s -wincheck -fixed 28999
```

健康标准：first-success 快、win=ok。

### 第 4 步：恢复 Docker Desktop（如使用）

启动 Docker Desktop 并等待引擎 Ready；若使用了内置 Kubernetes，需要在 Settings → Kubernetes 手动重新启用（节点容器不会自动恢复）。

### 第 5 步：最终验证

- [ ] 探针 3 轮全过 + win=ok（第 3 步）
- [ ] `wsl -l -v` 发行版状态正常

## 恢复后注意事项

- 若恢复后新端口**仍然**不可达（概率低）：重跑官方日志收集（collect-wsl-logs.ps1，需管理员）或考虑整机重启
- 恢复后如需补 200 轮直方图：

```bash
cd tools/wsl-loopback-probe
./wsl-localhost-probe -rounds 200 -timeout 30s -wincheck > hist200.log 2>&1
```

- 探针/日志收集工具在本仓库 tools/ 下，不依赖系统临时目录
