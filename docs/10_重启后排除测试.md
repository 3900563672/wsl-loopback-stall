## 一、结论摘要

1. **整机重启（09:27）后严重形态未复发，但健康态端口 0 注册失败窗口仍在**：固定端口地面真值（python http.server + Windows curl + netstat LISTENING PID 4140）全通；而 ephemeral 端口注册成功率仅 1/8~3/8（探针）、mix 一次 40/40 一次 zero 18/20 FAIL——窗口式、与重启无关，指向 2.7.8.0 缺 #41051（31 号文档）。
2. **Docker Desktop 排除（#62 闭环）**：Docker ON vs OFF 全部行为一致（probe 成功率、mix 窗口、Grafana 3/3 FAIL、固定端口 200、race refused→200ms 恢复）→ Docker 不参与本故障。
3. **探针工具缺陷（重要教训）**：`wsl-localhost-probe` 的 wincheck **从 08-18 起从未真正工作过**——① 探针只 Listen 不 Accept，curl 永远拿不到 HTTP 200；② `curl.exe -o /dev/null` 在 Windows 侧返回退出码 23（写错误），`cerr==nil` 判断永远为假。所有历史 `win=UNREACHABLE / curl-fail:000` 读数无效（不是环境证据）。已修复（Accept + 读请求 + 响应 200 + `-o NUL`），修复后首见 `win=ok:45ms`。
4. **Grafana 两个测试本地失败的机制精确化**：httptest ephemeral listener 注册未完成（健康态 ~200ms）时 proxy 立即拨号 → 502。这不是"WSL 回环 TCP 整体不可用"，是**注册时序竞态**（bind 返回先于 Windows 侧 listener 就绪）；CI（Linux 普通回环）无此竞态所以通过。之前的"网络栈残留"解释作废。
5. **tmpfs 覆盖 SOP 复跑成功**：Docker Desktop 重启后 5 节点 tmpfs 覆盖全部回来 → umount + chown（70:70 / 65534:65534 / 777）+ 删 Pod 重建 → 数据完好（PostgreSQL resource_events 560,684 且持续增长）。

### 2.2 A/B/C 三轮对照（#62）

| 轮次 | 条件 | probe（8s 超时） | port0_mix | Grafana ×3 | 固定端口地面真值 |
| --- | --- | --- | --- | --- | --- |
| A（11:35） | Docker ON（旧探针，无效 win） | guest 4/8 快 + 4 STALL；win 读数无效 | 40/40 OK | 3 FAIL | 29999：win 200 + LISTENING |

- 结论：Docker ON/OFF 行为一致 → **Docker 排除**；失败窗口随时间波动（B 轮 mix 40/40 vs C 轮 zero 18/20 FAIL），与 29 号"窗口式"一致。
- race 测试（Python，绑定后 t+0/t+200ms/t+1s 拨号）：t+0 必 refused（注册未完成）、t+200ms/1s OK——Grafana 测试失败机制的直接证据。

### 2.3 探针修复（probe_repro.go）

- 缺陷 1：只 `net.Listen` 不 Accept → 任何 HTTP 请求无响应。
- 缺陷 2：`curl.exe -o /dev/null` Windows 侧 rc=23（写错误）→ wincheck 的 `cerr==nil` 恒假。
- 修复：Accept goroutine（先读请求再写 `HTTP/1.1 200 OK`，避免未读数据 RST 丢响应）+ `-o NUL`。
- 验证：修复后 `win=ok:45ms` 首次出现；最小复现（Go 监听 + 读请求 + 响应）guest/win 均 200，服务端日志确认请求字节到达（79 字节 GET）。

### 2.4 集群恢复（Docker 重启后）

- 5 节点 tmpfs 覆盖回来 → umount（5 节点全成功）→ chown（prom 65534:65534/700、pg 70:70/700、jaeger 777）→ 删除 CrashLoopBackOff Pod（postgres/jaeger/prometheus/backend）→ 30s 内全部 Running。
- 数据校验：postgres PVC 2.2G / prometheus 275M / jaeger 724M；resource_events=560,684（09:40 恢复时 545,735，持续增长）。
- 端口：8080（dashboard 200）、18080（grafana 301）转发已重建。
