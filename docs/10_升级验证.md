## 四、回滚过程（重要踩坑，已实测）

1. `wsl --update --pre-release` 安装 2.9.4.0 成功（需数分钟）。
2. 回滚 `Add-AppxPackage Microsoft.WSL_2.7.8.0_x64_ARM64.msixbundle` → **0x80073D06**（已装更高版本 2.9.4.0）。
3. `Get-AppxPackage *WindowsSubsystemForLinux* | Remove-AppxPackage` → 移除成功（发行版数据在独立 vhdx，安全）。
4. 重装 msixbundle → **0x80073D28**（需要管理员权限）→ UAC 提权安装成功，Appx 包回到 2.7.8.0。
5. ⚠️ **关键坑**：Appx 包装完，`C:\Program Files\WSL\` 二进制**仍是 2.9.4.0**（wsl.exe FileVersion 2.9.4.0 / DLL 1.2.48.0），`wsl --version` 也仍报 2.9.4——该目录文件由 **MSI 组件**管理，Appx 只管 Store 身份。
6. **正确回滚**：下载 `wsl.2.7.8.0.x64.msi` → 管理员 `msiexec /i ... /qn` → `C:\Program Files\WSL\` 二进制替换完成（wsl.exe 2.7.8.0、DLL 1.2.14.0、sha256 3044acea... 与升级前一致）。
7. `wsl --shutdown` 后 `wsl --version` = 2.7.8.0 / 内核 6.18.33.1-1，完全恢复。

**09 号文档 3.2 节回滚指南修正**：Appx 回滚需配套 MSI 覆盖安装（或直接以 MSI 为准）；单装 Appx 不替换 `C:\Program Files\WSL\` 文件。

## 六、环境恢复备注：WSL 回环中继故障（2026-08-19 实测）

- 现象：Docker Desktop 重启后，WSL→Windows 的 localhost 中继失效——`com.docker.backend`（Windows 进程）监听 127.0.0.1:42839 但只收 TCP 不转发（Windows curl TLS 握手失败；WSL 侧连接 HTTP=000），kubectl 全部 EOF。
- 特征：**时好时坏**（14:51-14:57 全挂、14:59 恢复、Docker 再重启后又挂、15:0x 恢复）；控制面容器内部 API 始终健康（docker exec curl `https://127.0.0.1:6443/healthz` = ok）。
- 恢复路径（本次实测有效）：`docker desktop stop`（Windows docker CLI，优雅）→ `docker desktop start` → 等引擎 Ready → 中继恢复。
- 注意：Docker Desktop stop 会把 kind 容器全部置 Exited(128) 且**不会自动拉起**（restart policy 未生效），需手动 `docker start <5 节点>`；`/var` named volume 数据完好。
- 排查技巧：先 `docker port <ctl>` 确认发布端口，再分侧测试（Windows curl / WSL curl / docker exec 容器内 curl）快速定位故障层。
- 用户观察线索（2026-08-19）：**先启动 WSL、再启动 Docker Desktop 时出现概率较大**，疑似中继注册顺序竞态（未验证）；后续 2.9.5 验证时一并观察。
